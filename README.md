# CT Sequence Path Analyzer — 안전한 로컬 MVP

시퀀스 다이어그램을 보고 사람이 정리한 함수 목록과 순서를 입력하면, 제한된 C 문법에서 호출 경로·분기 조건·AUTOSAR RTE 연결 후보와 CT 2025 검토 사항을 JSON으로 출력합니다. Python 표준 라이브러리만 사용하며 네트워크·AI API·외부 프로그램 실행 기능이 없습니다.

## 실행

Python 3.10 이상. 별도 설치 패키지 없음. 저장소 폴더에서:

```console
python analyzer.py --source examples/synthetic.c --plan examples/plan.json --output report.json
python -m unittest -v
```

출력 파일은 새 이름이어야 합니다. 덮어쓰지 않습니다. 실제 분석 파일과 보고서는 저장소 바깥 또는 무시되는 `local/`, `reports/`에 두세요. `.gitignore`는 보안 경계가 아니므로 업로드 파일을 직접 검토해야 합니다.

## 입력과 결과 읽기

`plan.json`의 `sequence`는 반복을 포함한 목표 호출 순서, `entries`는 각각 독립적으로 탐색할 진입 함수 목록입니다. 소스는 `--source a.c b.c`처럼 명시적으로 지정합니다. 파일별 2 MB 제한이 있습니다. 일반 함수와 RTE 함수 이름을 모두 시퀀스에 쓸 수 있습니다. 조건부/반복 구간은 별도 plan으로 나누고 외부 스케줄은 사람이 검토하세요.

`candidates`는 진입별 후보 경로입니다. `events`는 호출 진입 순서와 인자 원문, `conditions`는 해당 경로의 기호 조건입니다. `priority`가 작을수록 먼저 검토하며 if/else-if의 마지막 else를 우선 탐색합니다. 다른 분기도 버리지 않습니다. `matched_prefix`는 목표 순서의 앞부분 중 일치한 길이입니다. 중간의 다른 호출은 허용하는 부분수열 방식입니다.

`order_candidate`는 구문상 호출 순서 후보일 뿐 실행 가능/성공 판정이 아닙니다. 모순 조건, 변수 변경, 미정의 동작, 스텁 동작 때문에 실제로는 불가능할 수 있습니다. `partial`도 불가능을 증명하지 않습니다. `unknown`에 나타난 진입점은 분석을 중단했으므로 후보 부재를 미도달 판정에 사용하지 마세요. `execution_verified`는 항상 false입니다.

`rte_links`는 분석한 진입 경로에서 `Rte_Read_`와 `Rte_Write_` 뒤의 이름이 정확히 같은 후보만 연결합니다. 다른 포트 이름은 매핑하지 않으며 후보가 중복될 수 있습니다. 데이터 연결은 함수 호출 관계가 아닙니다. ARXML, 포트 매핑, 반환값, 버퍼링, 실제 값 전달, runnable 활성화와 스케줄은 검증하지 않습니다. 관련 writer를 탐색하려면 writer runnable도 `entries`에 넣으세요.

합성 예제의 최우선 경로는 `Harness → Producer → Rte_Write_Status → Consumer → Rte_Read_Status → Target`이며 조건은 `status != 1`, `status != 2`에 해당합니다. writer의 인자 3은 후보 근거이며 read 결과가 실제로 3이라는 보장은 아닙니다.

## CT 2025에서 검토할 설정

1. 진입 runnable과 테스트 대상 함수를 결정하고, 여러 진입의 실행 순서를 별도로 설정합니다.
2. 조건식에 맞는 파라미터·전역 상태·RTE Read 출력 포인터 값과 반환 상태를 설정합니다. 도구는 구체 입력값을 풀어주지 않습니다.
3. 대상 내부 함수를 스텁으로 대체하지 않도록 하고 외부 의존 함수의 동작을 검토합니다.
4. Write 이후 Read, runnable 스케줄, 관측 시점을 확인합니다.
5. CT 실행에서 호출 순서·조건 커버리지·인터페이스 값을 실제 증적으로 확인합니다.

CT 2025 API/프로젝트/스텁 파일 형식은 현장 확인 전이므로 전용 설정 파일이나 TC를 자동 생성하지 않습니다.

## 지원 범위와 한계

일반 C 함수 정의, 직접 호출, 블록, if/else-if/else, return을 지원하는 휴리스틱 파서입니다. C 컴파일러/AST/전처리기가 아닙니다. 실제 AUTOSAR의 `FUNC`, `P2VAR`, MemMap, 조건부 컴파일은 직접 지원하지 않습니다. 승인된 로컬 복사본을 사람이 정규화한 뒤 원본과 결과를 대조하세요. 원본은 변경하지 않습니다.

루프, switch, goto, 재귀, 간접 호출, 중첩 호출, 전처리 지시문 등은 지원하지 않거나 중단합니다. 경로는 진입당 최대 256개, 호출 깊이는 32로 제한합니다. 복잡한 매크로/함수 포인터 선언/특수 확장은 오인식할 수 있으며 모든 미지원 문법을 검출한다는 보장은 없습니다. 조건식 안 괄호/호출/대입은 보수적으로 거부합니다.

조건은 소스 문자열이며 SSA·별칭·포인터·스코프별 값·상태 전이·부작용을 모델링하지 않습니다. 동일 이름 변수라도 시점과 함수 스코프가 다를 수 있으므로 자동 충돌 판정이나 여러 TC의 최소 개수 계산은 제공하지 않습니다. 각 경로의 조건을 검토해 TC 분할을 결정하세요. 실용적인 후속 단계는 컴파일 명령을 사용하는 AST 프런트엔드와 상태 모델, 실제 CT 증적 연동입니다. 이미지 인식·ARXML·TC 자동 생성은 범위 밖입니다.

## 보안과 테스트

고객사 코드·헤더·ARXML·보고서·경로·식별자·자격 증명을 커밋하지 마세요. 보고서도 인자와 조건 등 소스 정보를 포함합니다. 비공개 저장소라도 고객사 업로드 허용을 의미하지 않습니다. 이 저장소에는 새로 작성한 도구와 합성 예제만 있습니다. 외부 코드나 매크로를 실행하지 않습니다. 입력은 신뢰할 수 있는 로컬 파일로 제한하세요. 강한 프로세스 자원 격리나 완전한 악성 입력 방어는 제공하지 않습니다.

`python -m unittest -v`는 else 우선, 순서/반복, 상호 배타 분기, return, 재귀, 경로 제한, RTE 데이터/호출 구분, 미지원 문법, CLI와 출력 보호를 검증합니다. CT 2025 제품 환경에서의 검증은 별도입니다.
